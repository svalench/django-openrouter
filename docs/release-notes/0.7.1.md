# django-openrouter 0.7.1

The Pydantic AI extra no longer pulls the OpenAI SDK. No migrations. Upgrade from 0.7.0 is a package install.

## Highlights

- `django-openrouter[pydantic-ai]` depends on `pydantic-ai-slim>=2.64`, not the `pydantic-ai` meta-package.
- The meta-package installs `pydantic-ai-slim[anthropic,cli,evals,google,logfire,mcp,openai,web]`. Its `openai` extra requires `openai>=3.31` and conflicts with a project pinned to `openai<2` (for example natalai’s `openai>=1.59,<2`).
- `OpenRouterProfileModel` does not import the OpenAI SDK. `Agent` and the `Model` APIs the adapter uses are in `pydantic-ai-slim` itself.
- Docs: the README and the docs site show the usage dashboard in the Django admin dark theme as well as the light theme.

## Install

```bash
pip install "django-openrouter[pydantic-ai]"
```

That resolves next to:

```bash
pip install "openai>=1.59,<2"
```

Importing `django_openrouter` still does not import Pydantic AI. Without the extra, `OpenRouterProfileModel` raises `ImportError` and names the install command.

## Upgrade

```bash
pip install -U "django-openrouter[pydantic-ai]==0.7.1"
```

No new migrations. Chat, image, transcription and Pydantic AI call signatures are unchanged.

## Pydantic AI

```python
from pydantic_ai import Agent
from django_openrouter.integrations.pydantic_ai import OpenRouterProfileModel

agent = Agent(OpenRouterProfileModel("chat"))
result = agent.run_sync("Hello")
```

## Usage dashboard

Light and dark screenshots are in the README and on the docs site (admin page, every locale). The dark capture follows the Django admin theme toggle. Default path: `/admin/django_openrouter/requestlog/dashboard/`. Permission: superuser or `django_openrouter.view_usage_logs`.
