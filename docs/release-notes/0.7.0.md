# django-openrouter 0.7.0

Tracing, a staff usage dashboard, and Pydantic AI agents on the same usage profiles. Upgrade from 0.5.1. There is no published 0.6.0.

## Highlights

- Optional OpenTelemetry spans for every chat, stream, transcription and image call, including retries and fallbacks.
- Request logs group by `trace_id`, `session_id` and `metadata`, in the admin and in the file and ClickHouse backends.
- Staff usage dashboard: cost, errors, latency, tokens and profile budgets, with a vendored Chart.js build and no inline script.
- Optional Pydantic AI model that calls OpenRouter through a usage profile, so budgets, the kill switch and the request log still apply.

## New extras

```bash
pip install "django-openrouter[otel]"
pip install "django-openrouter[pydantic-ai]"
```

`[otel]` installs `opentelemetry-api` only. The SDK and exporter (OTLP, Logfire, Jaeger, Tempo, Langfuse) stay in the host project. `[pydantic-ai]` installs Pydantic AI 2.64 or newer. Importing `django_openrouter` does not import either extra.

## Upgrade

1. Install 0.7.0.
2. Run migrations. `0011_requestlog_grouping` adds nullable indexed `trace_id` and `session_id`, and nullable JSON `metadata`. `0012_requestlog_model_created_idx` adds a `(model, created_at)` index and depends on `0011`. Neither migration rewrites existing rows.

```bash
python manage.py migrate django_openrouter
```

3. Leave tracing off until you want spans. The default of `OPENROUTER["OTEL"]` is false, including when `opentelemetry-api` is already installed.
4. Give support staff `django_openrouter.view_usage_logs` if they should open the dashboard without access to settings. Superusers already can.

Chat, image and transcription call signatures are unchanged. `session_id=`, `metadata=`, `trace_id=` and `trace=` are optional.

## Settings

```python
OPENROUTER = {
    "OTEL": True,
    "OTEL_CAPTURE_CONTENT": False,
    # "OTEL_CONTENT_REDACTOR": "myapp.redact.redact_span_text",
}
```

| Key | Default | Effect |
| --- | --- | --- |
| `OTEL` | `false` | Parent span per call, child span per HTTP attempt. Off until this is true. |
| `OTEL_CAPTURE_CONTENT` | `false` | When true, redacted prompt and completion text are span attributes. Image and audio bytes are never copied. |
| `OTEL_CONTENT_REDACTOR` | unset | Dotted path `fn(text, *, kind) -> str`. `kind` is `prompt` or `completion`. |

API keys and `Authorization` headers are never span attributes. `BudgetExceeded`, `RateLimitExceeded`, timeouts and an interrupted stream (`499`) are span errors.

## Grouping

`bound_session()` works like `bound_username()`:

```python
from django_openrouter import chat
from django_openrouter.current_user import bound_session

with bound_session("ticket-42", metadata={"feature": "support"}):
    chat("chat", messages=[{"role": "user", "content": "Hi"}])
```

A call argument overrides the block for that call. Metadata keys on the call replace keys from the block. `session_id` and `metadata` on a chat call are sent to OpenRouter and stored on the log. `trace_id` and `trace` (extra span attributes) stay local. Retries and fallbacks of one call share a `trace_id`: the active OpenTelemetry trace id when a span is recording, otherwise a generated id.

## Usage dashboard

Permission: superuser or `django_openrouter.view_usage_logs` (the same people who can open request logs).

Default path: `/admin/django_openrouter/requestlog/dashboard/`.

The page is also linked from the OpenRouter admin index and from the request-log summary. It is registered on `RequestLogAdmin.get_urls` and wrapped with `admin_view`, so a custom `AdminSite` that registers `RequestLog` serves it under that site’s own prefix.

Day view buckets by hour (at most 7 days). Month view buckets by day (at most 366 days). Charts follow the admin light and dark themes. Headline cards compare the selected window with the previous window of the same length.

## Pydantic AI

```python
from pydantic_ai import Agent
from django_openrouter.integrations.pydantic_ai import OpenRouterProfileModel

agent = Agent(OpenRouterProfileModel("chat"))
result = agent.run_sync("Hello")
```

The adapter is a `Model`, not a `Provider`, so the profile chain, reservations, rate limits, kill switch and request log stay in this library. `conversation_id` is stored as `session_id` unless `bound_session()` is active. The adapter does not set `trace_id`; an active span, including `Agent(instrument=True)`, is the log trace id.

`BudgetExceeded` and `RateLimitExceeded` propagate to the caller and do not fall through to a model outside the profile chain.
